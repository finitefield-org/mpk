# Policy evidence roots and the API proof boundary

This intermediate W04 component defines private common
`mpk.policy.scan.v4`, `mpk.policy.evidence.v4`,
`mpk.policy.reproduction.v4` and `mpk.policy.receipt.v4` drafts.
[schema.json](schema.json) gives exact fields, hash rules, proof-state arms,
owners and remaining work. The new APIv4, AI-explanation and release roots,
complete Go ordinary assembly and reviewed migrations remain required.
W04 is In progress; no installed profile or released route changes.

Each root binds the complete context, selection, compiled policy contract,
captured frontend request/success and common VIR/map/frontend manifest.
Evidence additionally binds the complete VC and certificate manifest.
The exact immutable independent source authority is checked before any
cached observation can be used. A cached source ID cannot authorize a
modified row or a change from Go model data to retained native dispatch.
The preceding independent frontend/source and VC/skeleton validators remain
authoritative. No old helper or production source is edited.

The scan has a raw SHA256 identity over its complete canonical bytes.
Evidence, reproduction and receipt use their separate reserved v4 domains,
NUL and all fields except their own hash. Policy documents use canonical
narrow UTF8 JSON without LF. The existing depth768 canonicalizer avoids an
extra256-depth wrapper restriction; actual retained imports still enforce
their original limits. Carrier JSON files here end in LF, while each contained
policy value is imported and hashed as canonical bytes without that LF.
The graph is source/scan -> evidence -> reproduction -> receipt and has no
back edge into source artifacts or certificate manifests.

The observer calls actual unchanged public policy and API methods. All six
retained source bundles pass scan and API generation, including Rust32 and an
authorized synthetic-origin Go fixture. Two Rust bundles reach actual dual
zero-axiom certificate acceptance. Four other existing private source-shape
fixtures stop in the public certificate-assembly interface with
`Std.Bool operation received a non-Std.Bool carrier`. Those failures are
retained as assembly errors. They are neither compiler/source rejections nor
kernel type-mismatch counterexamples. The fixtures are not replaced to make
the certificate matrix appear uniformly successful. Complete general profile
preservation and application proof coverage remain migration/release work.

For the two checked bundles, the full actual native VC functions and statement
declarations match the retained common artifacts. A new untrusted adapter
changes only Certificate v0's opaque source-manifest payload to the entire
validated common certificate manifest. Both unchanged checkers then inspect
the identical resulting bytes. The export and axiom-report hashes stay exactly
unchanged; the certificate hash now binds the actual common source graph.
The evidence records both checker hashes, zero axiom counts, complete checked
declaration interfaces and exact embedded source bytes. It does not relabel an
old certificate hash as a new-source certificate.
The adapter independently recomputes the existing Certificate v0 domain hash
over the exact byte carrier,so copied valid reports cannot bless modified
bytes. The initial binding-gap trial and repair remain in the verification
record; no authoritative native proof result changed.

certificates, because source metadata is opaque to the kernel. Policy still
rejects a checked-Go claim: all169 complete Go theorem demands remain

A corrupted-magic control separately records format rejection, not a false
ordinary proposition. Caller `ready`, `proved`, registered-run, AI/CI authority,
modified source/VC/certificate links and omitted Go demands reject.
