# Common VC/certificate links and Go theorem-demand draft

This W04 draft adds common VC v4 and certificate-source-manifest v3 roots,
retained-profile skeleton v4 regeneration and two Go-owned theorem-demand
identities. The [catalogue](schema.json) records exact root fields, canonical
limits, semantic requirements and production owners. Eight
[proof bundles](artifacts.json) bind the preceding VIR/map/frontend manifests
to proof work. Go ordinary proposition expansion and final ordinary-context/
skeleton representation remain required before the complete W04 freeze.

| Artifact | Identity | Hash domain |
| --- | --- | --- |
| Common VC | `mpk.vc.v4` | `MPK-VC-4.0` |
| Certificate source manifest | `mpk.source_manifest.certificate.v3` | `MPK-SOURCE-MANIFEST-CERTIFICATE-3.0` |
| Retained skeleton | `mpk.vc.cert_skeleton.v4` | no own public hash |

Every hashed root binds all required members except its own digest, including
schema, full context, source references and all functions/requests. Exact
compiled VC/manifest profile-contract v2 identities follow the validated whole
context. The common VC has disjoint context-selected root fieldsets: retained
profiles keep `functions` and their verification-limit identity; practical Go
has the complete theorem-demand program and derived unavailable-expansion
marker. Caller extensions, crossed contexts, stale source hashes and rehashed
changed members reject against full source regeneration.

The [consumer](../../../../probes/go-practical/proof_artifacts.py) first checks
the exact preceding source artifacts. Its native generation query is rebuilt
from those source values and independent captured authority, then compared in
full before execution. A valid query from another map/permission authority
cannot supply a borrowed VC. Retained native data and generated skeleton
declarations are copied through a nonrecursive JSON clone; mutating a returned
skeleton cannot change the independent generation authority.

Retained functions and theorem declarations stay directly at their root.
The unchanged production canonicalizer supports a maximum of768 JSON
containers; adding a nested payload around old term arrays would spend an
extra container. The flat fieldsets preserve their original depth. The new
[Python parser/canonicalizer](../../../../probes/go-practical/proof_canonical.py)
and [independent Go observer](../../../../probes/go-practical/proof_hashes.go)
retain256MiB input/canonical bytes,depth768,1MiB decoded strings,safe integral
metadata,Unicode scalar strings,UTF16 key order and domain-NUL hashing.
Parsing,canonicalization and cloning handle deep containers without Python
recursion-limit dependence. Earlier64/256-depth helpers remain unchanged.

The [native observer](../../../../probes/go-practical/proof-native/src/main.rs)
calls unchanged public successor source validators and actual
`generate/import_successor_vc`, `emit/import_successor_vc_skeleton` and
certificate-stage manifest import. Official compiled VC profile envelopes are
supplied to those validators. Full VC functions,members,groups and skeleton
statements are regenerated; native rejections cover missing members,altered
conclusions/groups/statement bodies,nested fields and wrong required-check
profiles. The new common importer compares complete generated JSON as well.
Its [build](../../../../probes/go-practical/proof_native_build.py) preserves
original dependency versions/checksums and226 unchanged linked production
source files. No facade,production parser,core or Certificate v0 is modified.

Five [baselines](baseline-queries.json) preserve complete old VC,skeleton and
certificate-stage manifest values for Go fixed,Rust32/64,C# and Java.
Go/Rust64 start with original fixture source roots; the other target contexts
use independently formed old-family inputs. The additional authorized
synthetic-Go source case remains supported. Forty-four native queries contain
both intact and actual source-regeneration/profile-policy negatives. These are
fixture comparisons and generated statements; proof discharge remains distinct.

The [Go demand builder](../../../../probes/go-practical/go_obligations.py)
defines19 closed request families. Every request pins full typed context,
VIR,source scope,function body,contract,requirement,origin and exact dependency
request IDs. Fixed family/member coordinates resolve through the captured
typed body and concrete operation definition. Arbitrary predicate text or a
caller proof flag supplies no semantics.

Requests denote registered theorem obligations over all reachable dynamic
activations under the exact explicit entry/profile/contract conditions.
They cover function source refinement,entry representation,frame,partial
correctness,clause definedness and each requested postcondition. Even a
zero-node function has source/function/contract/control obligations. Region
control includes normal/abrupt exits and resume continuations. Loop requests
cover invariant definedness,initialization,preservation,exit and candidate
rank domain/decrease on continuing backedges; missing total variants remain
pending. Existing current/prefix-state access and same-invocation recipes are
retained in full. Their truth still requires ordinary definitions and proofs.

Calls require exact same-U callee source-body/contract dependencies plus
caller-side precondition and relation obligations. Defaults contribute no
trusted callee theorem. A total caller adds termination at its actual call
arguments; the default partial callee is not silently assigned a global
termination promise. Registered adapters retain their exact captured source
binding demand. Source/AST/lifetime/control/call correspondence remains due.

The current private foundation has no complete registered elaborator for
these source/operation theorem requests. All169 request IDs in the two Go
examples therefore remain unelaborated. Skeleton requests raise
`OrdinaryElaborationPending`; an empty skeleton or caller-supplied expanded/
ready context cannot promote this state. The requests are typed demands,
not ordinary propositions or proofs. Final Go ordinary signatures/definitions,
statement expansion,program assembly and skeleton fields remain W04 work,
with their production implementation/proofs required in T02–T06.

The certificate source manifest references the exact frontend-manifest and
validated common VC schema/hash. VC generation refers only to the frontend
manifest,keeping the dependency graph acyclic. This linked metadata carries
no proof result; a Go demand VC still cannot produce a proof skeleton.
Registered practical frontend/toolchain/release provenance remains a separate
required boundary from the preceding capture-artifact draft.
