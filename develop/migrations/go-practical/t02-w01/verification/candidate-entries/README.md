# Candidate-bound source entry equations

A validated graph-and-contract binding can now derive the existing complete
source entry catalogue from its own contract module's value domain. The
returned owner retains the candidate request, original source selection,
contracts and independently imported graph together. A caller cannot substitute
a different value domain in this handoff. The catalogue and its certificates
remain untrusted candidates: retaining the graph alongside the catalogue does
not make a certificate itself an authentication of the graph or capture.

The affected Rust graph test imports both complete original owners, with 5,697
and 5,667 source/export objects. Each independently resolves its original
same-named `Root`, while crossing their owners rejects. The 5,697-object owner
also derives the original one-input, one-result entry layout and a complete
entry-equation assembly for that selected function. The unchanged Rust and Go
checkers accept its identical 473,423 bytes with 2,063 declarations, zero axioms
and equal export, axiom-report and certificate hashes. The certificate hash is
`ccc8d54ef3741a702c6b523faba1f7aebbf0fa92ab5aac991efc4688d7201d0b`.

The complete live Go capture and independent Rust observer passed with all 182
original packages, 5,516 source objects, 181 export objects and 5,577 registered
SDK files. While both root sets remained held, the observer derived and checked
the entry equations from the bound candidate and original module graph. The Go
checker also accepted those exact live certificate bytes, with the same counts
and hashes as Rust. The other complete owner with a same-named root was again
rejected when crossed; the test-only installed-SDK owner bound the correct
inputs. This capture has no user contract overlay: its default `true` contract
and entry equations are not an application theorem. Go 1.25 ran as Linux/amd64
under local emulation, and the Rust observer ran on Linux arm64; this is not a
native Linux release or installed-launcher acceptance.

The graph test and full live capture were selected because they exercise the
new graph-to-entry handoff and its held-root consumer without changing their
original input scope. Strict Clippy passed for the affected Rust graph test and
the Linux observer, including its test-only configuration. Changed Rust files
passed format and diff checks. An initial live attempt stopped before capture
because its temporary evidence parent directory was missing; the fresh rerun
used the full original inputs after creating that directory. An initial attempt
to lint with `cfg(test)` globally produced unused test-code errors in unrelated
dependencies; the successful scoped run applied it only to the observer. No
unrelated suites or new validation archives were added.

These equations concern entry environments, not valid-entry assumptions,
source execution, source/IR correspondence, storage/frame/callee properties,
a complete checked foundation or an installed context. R01 and T02-W01 remain
open, the practical profile stays inactive, and the cumulative
`./scripts/check-fast.sh` gate is deferred to final T02-W04.
