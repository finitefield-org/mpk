The [byte-image builder](../../../../../../go-tools/go2vir/practical_replay.go)
keeps launcher-authorized original root paths with sealed owned bytes. It
materializes captured files under a private mirror of those original paths.
Relative, absolute and versioned replacement directives remain byte-exact;
no go.mod, function body, import or type signature is rewritten or stubbed.
Source identities, full captured namespace records and original root bindings
remain independently owned. Present-but-unread names retain not-captured
status; they never acquire invented bytes or evidence of absence. A consumer
must still bind every consulted namespace/input to the eventual private context.
The byte image alone does not claim complete general namespace equivalence.

All input snapshots share the unchanged candidate/input/contract/directory/
byte limits. Two individually valid144-MiB snapshots reject when combined
past the256-MiB source limit. Mutated origins, missing ownership, rehashed
snapshots, crossed paths and duplicate inputs reject. Full original compiler
files are copied as bounded streams under the compiler inventory's own schema,
then the copied5577-file image is independently validated. Compiler binaries
are not disguised as source objects or charged against an invented source cap.
Actual kernel read-only mounts protect execution; ordinary file permissions
alone are not a claim of production isolation.
