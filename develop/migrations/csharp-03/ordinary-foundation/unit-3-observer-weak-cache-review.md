# W09 weak argument memoization — scoped direct review

This is a follow-up experiment to `unit-3-observer-cache-experiment.json`,
limited to the test observer. No generated definition, certificate, checker,
frozen bound or application-proof requirement changes.

The observer can now reuse an evaluation for the same live function/suspension
or cube view. The per-lambda FIFO contains at most eight weak keys/results.
Boolean and statically unused arguments retain their existing handling.

Reviewed the following correctness and lifetime requirements:

- Key equality uses the original allocation identity, with body/environment
  identity for closures and offset/stride/length for cube views. Weak references
  keep the control block allocated, preventing a different allocation at a
  recycled address from matching a dead key. Equivalent-looking fresh values
  are not conflated.
- Lookup never forces a thunk. Forcing a shared thunk preserves its identity
  and meaning. Boolean results that become available still use the Boolean
  cache; function-valued suspensions can use the weak identity cache.
- Cached closures and suspensions use weak result edges as well as weak keys.
  A returned closure that captures the memoized function must not form a strong
  cycle. Dead keys/results are pruned on insertion; an expired result is a miss.
- Unsupported values retain normal evaluation. Eviction affects reuse only,
  not the result or evaluation demand order.

New targeted regressions exercise shared function/suspension work, different
captured values, dense/sparse cube views, eviction after sixteen live views,
argument/suspension release and the explicit `f -> result capturing f` cycle
hazard. Existing laziness, Boolean truth, high-binder, environment-release and
closed-definition tests remain in the selected twelve-test filter.

No additional semantic correctness finding was identified in this scoped code
review. Actual workload behavior is still being measured and is not accepted
as a performance improvement. The original domain suite and all outstanding
W09 units retain their full completion conditions. Final commands, source
hashes and pending jobs are recorded separately in
`unit-3-observer-weak-cache-experiment.json`.


## Optimized execution follow-up

A three-second live sample of the debug duplicate-map probe showed 330 of 1,631
worker samples in memmove and 92 in a memcpy stub, alongside generic core
reduction. This motivates measuring the same case in a release build; it does
not establish a speedup. The duplicate case still checks all 32 result bits,
uses the original C33 input and keeps unconditional assertions. All twelve
observer regressions also pass in release mode (0.01 seconds).

Once the release case started, the redundant debug probe was explicitly
terminated with SIGTERM. Its nonzero process exit is retained as a cancellation,
not a semantic failure. The older formal domain suite remains running. The
optimized workload has no verdict yet; no generated bytes, evaluation rules,
frozen limits or acceptance criteria changed for this measurement.
