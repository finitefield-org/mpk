# W09 unit 4 missing/null boundary rules: component review

The new generator consumes an immutable emitted data phase and confirms every
attached contract belongs to the independently regenerated boundary VC set.
It binds the source, foundation, binding VC and boundary VC identities. Each
new symbol is an actual demanded W07 MissingRule or NullRule with the field's
source carrier argument and a Boolean result.

Required/rejected omission and forbidden null are false predicates. An exposed
missing arm, admitted null arm or exact frozen typed default is an ordinary
literal. Source values are projected using the existing binding definitions
before proof-level typed observation equality with that value. This preserves
decimal normalization and active sum/presence semantics; it does not substitute
the non-reflexive floating `.equal` operation. Source representation/domain and
reconstruction obligations remain separate and must still be proved.

The literal emitter takes and returns the same Builder and validates every
constant. All prior declarations and costs remain in the context. The source
tests compare the full predecessor binding-relation declaration closure,
including definitions not directly used by the new predicates. Import rebuilds
the full program and canonical certificate, rejecting metadata or context
substitution. Unresolved boundary VC symbols remain explicit; these two field
rules do not implement AcceptInput, DecodeSource, output formatting or proofs.

Verification uses the15 original contracts already accepted in the W07 golden
set. It covers required/rejected rules, nullable Option/presence, expose-missing,
frozen scalar/enum/Option/presence defaults, alternate decimal scale and swapped
source tag values. The independent source projection oracle reads original facts
and binding rows, and the existing storage encoder supplies actual core inputs.
Tests compare generated Boolean definitions against typed rule outcomes.
