# Native calendar/time/Guid operation relations

This unit-5 component reuses the eight original native inputs and captures in
`../calendar-clauses/`. Requests and responses are pinned here byte-for-byte.
The generated program independently reconstructs W03 semantic signatures,
source function/node and SSA subjects, result relations, normal/exceptional
successors, and original check/prefix/failure/success predicates. Exact metadata
and certificate reconstruction is required by import. Other data families,
Money, and Instant error-outcome signatures remain explicitly pending.

The scalar result/success/failure definitions and their transitive closures
match the existing Calendar and Temporal ordinary programs. Only signatures
with at most one exception are admitted: their ordered failure predicate is
also the independent raw condition. Multi-condition signatures are rejected;
error-outcome results require a separate adapter. Result equality uses a core
Let to share the computed value across all physical bits, including all 128
Guid bits. It does not evaluate source code or assume an application theorem.

`certificates.json` records the eight generated byte sequences, 57 definition
occurrences and 67 use points. All 52 unique operations passed 124 result/guard observations; exact
verification status, including the completed eight-case dual-checker run, is recorded in
`../unit-5-calendar-data-progress.json`. Runtime cases cover one source use point per distinct operation;
all 67 use points receive exact source/definition reconstruction checks. Correct
and high-bit-corrupted results are compared with the independent T03 business
oracle, including range/overflow guards. The standalone scalar semantics remain
covered by their unchanged definition closures and existing tests.

These definitions are not native-body/application proofs. Original units 3–8
and W09 remain incomplete. The full T06 gate is deferred to T06-W12.
