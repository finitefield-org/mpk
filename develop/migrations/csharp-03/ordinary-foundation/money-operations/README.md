# Ordinary Money operations (partial W09 internal unit 4)

This component is not a unit-4 or W09 completion receipt. The original eight
internal units and their exit conditions remain in `../implementation-plan.md`.
Bindings, canonical boundary codecs, source-body proofs, transition relations,
application proof assembly and final W09 acceptance remain required.

The generator independently reconstructs each reachable concrete Money
instance, its amount/currency storage, and all ten frozen operation signatures,
equations and ordered errors from validated original VIR. It emits uninvoked
operations too. Ordinary decimal circuits implement add/subtract and checked
multiply/divide followed by explicit rounding. The five rounding modes are
selected by a complete u32 input; scale validation rejects negative i32 values
and values above 28. Currency-first structural comparison and decimal value
comparison reuse the ordinary relation definitions. Construction preserves the
original exact decimal cohort and currency storage.

Create takes an explicit additional ordinary parameter of type
`currency carrier -> Bool`, followed by its three frozen value arguments. Its
metadata records this parameter on the normal definition and all failure
predicates. This is the source currency-predicate obligation's parameter, not
an invented currency whitelist or a source proof. Later native-body lowering
and proof assembly must supply and justify the actual source predicate.
Other operations have exactly their frozen value arguments. Ordinary normal
functions and ordered failure predicates are total definitions; domain
preconditions and the absence of earlier failures remain caller obligations.

Two original sources contribute three Money instances and all 30 operations.
The existing `binding-vc-money` source uses a string currency. The additional
`shared-string-enum-money` source holds both Money<string> and Money<source enum>,
with captured source declarations and content-bound bindings. Its Linux capture
runs twice with deterministic output, no network and a read-only repository.
Generation, exact regeneration import, signature/error comparison and
metadata/certificate mutations passed for both sources. The original pin and its
metadata remain byte-identical when the second source is added. The maximum
candidate has 147,163 terms, 1,599 declarations and 10,439 counted static
transformers, within frozen structural limits. The bytes here are pinned
candidates. The original binding-vc-money pin passed both unchanged checkers
with zero axioms and hash-corruption rejection. The supplemental shared
string/enum pin also passed both checkers with zero axioms and corruption
rejection. The shared 22-case semantic run passed (3,950.06 seconds); the original
78-case run subsequently passed in 18,164.08 seconds. Both actual ordinary
executions retain their original inputs and generated bytes; the current
100-case named-error oracle audit checks the strengthened observer condition.
The separate semantic test executes ordinary terms against the independent
MoneyModel oracle for 78 cases, including exact cohorts, signed zero, precision,
all rounding modes, arithmetic overflow, currency priority and ordered errors.
An additional test observes all 20 operations from the shared string/enum source
in 22 cases; this run passed. Its first compile attempt omitted the enum oracle's underlying type;
that test-data error was corrected before execution. During direct review, the
comparison helper was also strengthened so an unexpected unnamed oracle error
cannot match the absence of a generated failure. These semantic runs use
the previous assertion and are retained as versioned evidence; a separate audit of the identical 100-case matrices passed the strengthened
named-error condition. This audit does not execute generated operation bodies
and cannot replace the ordinary semantic runs. Finite observations are not
universal application-VC proofs.

Initial generation exposed duplicate emission of the D9 helpers used by decimal
relations/rounding, and an attempted reference to a nonexistent word-equality
helper. Round selection now reuses already-emitted cube helpers and compares
complete mode words using the existing unsigned Less function in both directions.
The common builder still rejects duplicate global definitions. No checker rule
or certificate format has changed.
