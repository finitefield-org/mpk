# Canonical typed JSON depth candidates

Fifteen original boundary-attachment source candidates and one active-depth
helper retain actual ordinary definitions for the depth32 check. Source tests
compare against independent captured canonical typed trees (167 observations);
the helper supplies252 active-node, inactive-storage and overflow cases.
All16 module hashes were recomputed before publication. Per-source metadata and
aggregate rows agree, and all15 source identities match the accepted corpus.

The unchanged Rust and Go checkers accepted all16 identical byte sequences,
with matching reports, zero axioms and rejection of corrupted hashes. See
`../unit-4-json-typed-depth-progress.json` for terminal versus live evidence.
The predicates assume valid semantic representations. The new depth-guarded envelope variant connects them to decoded arguments;
its combined verification remains in progress. Node limits and application
proofs remain separate obligations.
