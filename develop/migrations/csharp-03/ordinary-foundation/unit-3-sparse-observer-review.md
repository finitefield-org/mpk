## Change and rationale

The C33 two-entry string map spends excessive core reduction work checking
large zero padding regions. Its first length-padding sibling has depth 31.
Storing only 13 true input leaves previously reduced memory without identifying
equivalent empty subviews for application memoization.

The test-only observer now uses `UniformCube(bit, depth)` for complete constant
truth tables. Sparse view projection returns a false uniform cube only when
no stored true address matches the complete selected offset/stride range.
Every other address is already false by the sparse input representation.
This is a representation normalization, not a domain acceptance shortcut.

The bounded per-function identity memo admits these exact value/depth keys.
An evaluated suspension can expose a canonical argument. When a function body
first demands a fresh suspension and a cached result exists for the now-known
argument, the evaluator drops that invocation's remaining body frames and
returns the cached result through its original memo frame. The check uses the
same function's memo identity and the exact demanded suspension Rc, never just
an address without a live owner or a generated definition name. Pending
arguments are not forced for lookup. Nonconstant closures remain weakly cached.

Optional per-thread core-step and elapsed-time limits fail with an explicit
diagnostic. Limits accumulate across evaluator calls/output-bit reads and have
no effect on proof/checker admission. Default runs remain unlimited. The
recommended commands use limits to avoid another hours-long diagnostic run.

## Static review boundaries

- Exact sparse membership includes offset, stride, original length and high
  address bits. Nonempty views retain their sparse data; only empty views drop
  that backing. The uniform value's depth is part of the memo key.
- Uniform projection still demands its selector. Memo lookup never forces an
  argument that was previously unused or on an unselected branch.
- Demand-triggered reuse keeps the owning function memo continuation. Other
  discarded pending thunks can safely recompute later; the evaluator has no
  mutable effects or executing/blackhole state in those suspensions.
- Cache capacity, weak edges and closure-release behavior are retained. No
  global strong closure cache or host operation evaluator was introduced.
- The observer-only revision preserved generated bytes, but did not bound C31
  work. The revised generator changes wide zero-region definitions and bytes;
  capacities, every inactive-storage check and checker rules remain unchanged.
  Current fixtures and checker receipts must be refreshed before acceptance.

New regressions check all small-cube addresses, C33 high-address corruption,
true/false uniform projections, reuse across different fresh backing stores,
source release, a changed demanded bit, unused/poison selector behavior,
closed-function value-cache eviction, and cross-certificate isolation.
The actual C31 generated predicate is tested at full size, with a measured
transition ceiling and three nonzero-address rejections. Existing observer
regressions remain required; static review alone cannot establish a speedup.

## Revised fixed zero-region generator

The user run exhausted 500,000,000 transitions in 7.89 seconds before returning
the C31 positive result. Preserving the counted-fold implementation was not a
sufficient optimization. No limit was increased in response.

For d > 5 the generator now emits `Zd(s) = Z(d-1)(s false) AND
Z(d-1)(s true)`. The d <= 5 scalar truth tables remain unchanged. The two
branches partition all physical addresses, including inactive storage, so a
successful result requires every leaf to be false. Child globals are defined
before parents; these are ordinary acyclic Boolean definitions, not recursive
certificate primitives. There is one shared definition per depth. Existing
collection folds and their transformer budgets are unchanged.

Static review checked De Bruijn source index zero, one selector removed per
branch, child input depth, Boolean output, emission order, retained depth-253
limit and reuse by name. The zero-only test now expects zero fold transformers.
The unrelated aggregate-fold reconstruction assertion remains 8,217.

The C31 regression bounds each fresh positive/negative observation by one
million transitions and logs each count. It still checks the first, middle and
final nonzero addresses; the existing dense small-cube exhaustive and padding
mutations remain required. The user-reported C31 counts above satisfy this
requirement; the user subsequently reported the observer/padding regressions
passed as well. Uniform sparse-view memoization is still required for sparse runtime;
binary expansion alone does not make arbitrary dense functions cheap.

Reading existing fixture declaration names identified twelve affected current

Historical snapshots and successful receipts are retained as historical evidence.
No fixture generation, compiler or checker was run by the agent. Regenerated

## Active count and inactive-tail revision

Static inspection of `Domains::sequence` found that its saturated sum always
received `2^indices`, including all unused slots. It returned early for invalid
ordering because INVALID saturates the sum, but valid maps continued across
all capacity. Child string domains used the same scan. Fixed padding checks
alone could not eliminate this work.

The sum now receives the validated logical length and retains the existing
counted fold and saturated addition. `ZeroTail.Ii.Dd(length, source)` separately
checks every physical inactive slot. At length zero it calls the full zero
predicate. At length >= the current subarray capacity it returns true; the
outer sequence length guard independently rejects lengths above the declared
capacity. In partial regions, an entirely zero region satisfies the tail;
otherwise both branches are checked with ceil(length/2) for even indices and
floor(length/2) for odd indices. This follows the physical LSB-first layout.
The initial half-length/add-one implementation failed both user-run tail
regressions at 500 million steps per thread, with only the three wide length-zero
observations completing. Total test time was 15.00 seconds. This representation
was replaced by the original-bit/scalar-carry recurrence described below.

Review checked the original implementation's child-first declaration order,
decreasing index depth, array
projection after the tag/padding selectors, and coverage beyond non-power-of-
two capacities. The declared bound still guards the entire count, ordering
still applies between adjacent active elements, and element domains and own
cell/saturation semantics remain. No evaluator or checker changes were made.

New regressions enumerate all eight-slot Boolean arrays at every length,
all physical addresses with wider child payloads, and the single-slot base.
Wide sparse cases cover empty/odd/half/full lengths and first/last inactive
corruptions at full I14/D4 and I12/D20 sizes, with measured-work assertions.
A source probe retains the exact increasing C33 string map and then independently
corrupts the first unused entry and final physical address. No capacities or
original six-suite cases were removed. The new code was formatted and reviewed
but not compiled or tested by the agent; user execution remains required.

## Scalar carry correction after the tail-test failures

At step offset k, let q = original_length >> k, b = q mod 2 and c be the
incoming Boolean carry. The active count is q+c. Its even and odd subarray
counts are respectively `(original_length >> (k+1)) + (b OR c)` and
`(original_length >> (k+1)) + (b AND c)`. Thus no intermediate word, shift
closure or increment closure is needed. The implementation reads original
length bit k at a fixed address and propagates only the Boolean carry.

The wrapper passes carry=false and invokes steps only when length < 2^indices.
At each step, the active subarray is empty iff all remaining original bits and
carry are zero, and full iff all are one. After all index bits are consumed,
carry alone decides whether the single slot is active; an inactive child must
satisfy the complete zero predicate. Empty/full/entirely-zero shortcuts and
physical address projections preserve the original coverage. The outer domain
still enforces declared capacity independently.

Static review checked the four b/c combinations, boundary length 0 and full
capacity, odd/even branch orientation, and binder indices: wrapper length=1,
source=0; step length=2, carry=1, source=0. Original length is passed unchanged
through all steps; child definitions precede their parents. The step recursion
has at most 14 index levels. Generated names include original index width,
child width and offset, preventing cross-width reuse. No cache, evaluator,
checker, work ceiling, expected verdict or test-case coverage was changed.
The user subsequently ran these same small exhaustive and wide sparse tests:
both passed in 0.58 seconds total (30.20 seconds compilation). All 38 wide

## Large active collections: scalar observations and exact unit counts

The user reported step exhaustion at 256 validation errors and 16,384 UTF-16
units. A bounded scalar-only observation tree now preserves previously observed
bits after intermediate selector closures expire. Each tree has at most six
selector levels (127 nodes), and owns no V, Env, suspension or LambdaMemo.
Only known/demanded Boolean arguments select a path; no poison argument is
forced for lookup. Returned lambdas share the corresponding observation subtree,
but their environments still use the existing weak-result lifetime policy.

A new test reads every address of a five-selector parity function with an
expensive suffix, releases intermediate closures, repeats the reads and checks
both exact values and a reduction-work decrease. It also asserts that weak
selector-closure handles expire while scalar observations remain available.
All 18 ordinary-core regressions passed, including laziness, weak lifetime,
capture-cycle and cross-certificate checks.

The observation cache fixed the 256-error boundary but the full UTF-16 case
still exhausted its step budget. The generator now replaces the sum of active
constant-one counts with length only when the element is an unconstrained
full-width bit scalar and the sequence has no ordering. Range/enum domains,
non-power-of-two padding, wrappers and declared public clauses are excluded.
The normal fold remains for those cases. Length and tail guards remain outside
the shortcut, and the same saturated own-cell addition still applies.

## Total-cell timeout correction (2026-09-20)

The user reported 606.15 seconds with no result for the first 65,536-cell case.
Fixed product-field aggregation and dense-to-sparse normalization alone did not
finish under a 45-second diagnostic cap. A temporary scaling probe measured
0.093 / 0.125 / 0.429 / 1.641 / 6.510 / 25.944 seconds for 1 / 2 / 8 / 32 /
128 / 512 elements, showing approximately linear per-element cost. The temporary
probe was removed; the original full boundary test is unchanged.

The shared saturated adder was evaluating a register-cube circuit for every
accumulated value. Its replacement guards both arbitrary u32 operands against
65,536, adds the low 17 bits with an explicit carry, and saturates at 65,537.
An input is invalid iff any bit above bit 16 is set, or bit 16 and any lower bit
are set. For valid inputs the 17-bit sum plus carry is exact; carry or bit 16
with any lower sum bit selects the sentinel. Left-invalid selection encloses
right-invalid selection and the arithmetic, preserving lazy early rejection.
The small circuit uses shared Bool lets outside the five output selectors.
The existing 256-binder limit is enforced before emission and again by normal
certificate validation; no limit or checker rule changed. A first attempt to
lower the old full circuit directly exceeded that limit and was discarded.

Review of product simplification: only unrestricted, power-of-two full-width
bit scalars can contribute a compile-time one. Public clauses, enums, ranges,
wrappers and padding-sensitive widths retain their domain calls. Every physical
field/unused-role padding check remains, and the remaining nonconstant field
checks retain their order. Reordering constant nonnegative ones around saturated
addition preserves the result and cannot hide a field failure.

Review of dense normalization: only concrete power-of-two tables with at least
1,024 entries are candidates. Index collection stops above length/64 true bits
and falls back to the original dense backing. All other tables also stay dense.
The sparse representation preserves every address; an empty projection can use
the existing exact uniform representation. No generated definition name or
expected answer is inspected. Tests compare every address against dense storage
at/below/above the threshold and check a demanded invalid selector still fails.

The final full source test passed in 38.19 seconds, checking both 65,536 and
65,537 cells; measured peak footprint 564,020,040 bytes (537.89 MiB). The scaling
probe's 512-element case fell to 2.462 seconds. The original timed-out run has no
memory peak, so no comparative memory reduction is claimed for this change.
The new adder passed 4,624 operand pairs (carry boundaries, all high-bit positions,
u32 maxima) and four invalid-left/poison-right probes. Both unchanged checkers
accept the same standalone certificate with zero axioms. Source regressions (7)
and core/recursive/aggregate behavior regressions passed. The sharing test's old
expensive predicate was itself this adder, invalidating its >2 cost-ratio premise
