# Ordinary ordered input object candidates

These 16 Certificate v0 candidates compose complete ordered object parsing with
semantic argument storage. Fifteen original boundary-attachment sources supply
29 accepted input documents; an original empty-input source supplies `{}`.
The targeted runs passed all 30 complete output packets and rejected 32 mutated
documents, including duplicate, unknown, reordered and missing required fields.
Every predecessor field decoder definition and dependency is preserved.

Publication independently recomputed each module certificate hash and compared
it with both metadata locations, checked per-case metadata against aggregate
rows, and checked the 15 attachment source identities against the original
accepted corpus. Maxima are 144,703 terms, 2,204 declarations and 7,356 counted
static transformers. Tests without an output directory compare generated
metadata and certificate bytes with these pinned files.

The unchanged Rust and Go checkers are checking all 16 identical byte sequences
for acceptance, matching reports, zero axioms and rejection of corrupted hashes.
See `../unit-4-json-envelopes-progress.json` for actual terminal/live evidence.
Parser execution and certificate typing do not establish AcceptInput or the
source application theorem. Canonical typed-value bounds, the raw-node bound,
source constraints, reconstruction, output and remaining W09 work are open.
The T-wide gate stays deferred to T06-W12.
